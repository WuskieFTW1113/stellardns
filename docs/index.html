A resolver built for game downloads, not just ad blocking.

StellarDNS answers your cache IP for every launcher domain, races upstreams so a slow forwarder cannot add its latency to every lookup, hides that it is filtering at all, and now updates itself from the console — plus an encrypted client so laptops get the same policy off your LAN.

What it actually does

Every claim below is a behaviour you can watch in the query log.

⇄ LANCache without lancache-dns

Name a category, give it your cache address, and every domain it owns resolves there — one static answer, no second container to babysit. Toggle a launcher off to return NXDOMAIN instantly.

steam · epicgames · xboxlive · battlenet · riot · uplay

⚡ Hedged upstreams

Start the fastest forwarder; if it has not answered in 60 ms, start the next one too and take whichever answers first. A slow-but-alive upstream stops taxing every query.

adaptive SRTT · circuit breaker · serve-stale

⊘ A sinkhole that does not look like one

Blocked answers come from this host's address on the client's own subnet, with a per-name TTL derived by hash, NODATA with a synthetic SOA where NXDOMAIN would be a lie, and no Extended DNS Errors on any block path.

no constant TTL · no EDE 15/17 · stub answers 404

⌂ Real internal DNS

Local records, conditional forwarders, Active Directory zones including _msdcs and SRV records, Bonjour/mDNS-adjacent name handling, and private PTR sent to your DC.

internal TTL capped at 30 s · never served stale

⤒ Updates from the console

Check GitHub, review the release notes, install. The new server.js is node --checked before it replaces a working one, the old files are backed up, and one click rolls back.

https-only · host allowlist · checksum when published

⛊ Encrypted client

A local resolver for your laptop that speaks DoH or DoT upstream, so the same policy travels with the machine. Windows shell uses WebView2, Linux ships as an AppImage with a CLI, macOS is native Swift.

127.0.0.1:53 · DoH/DoT · blocklists · GUI + CLI

Install

Debian, Ubuntu, Alpine and anything with systemd or OpenRC. Node 18 or newer.

# one line, on the box that will answer DNS
curl -fsSL https://github.com/WuskieFTW1113/stellardns/releases/latest/download/stellardns-install.sh | sudo sh

# then open the console
http://<server-ip>:5380

# it prints the generated admin password once; change it in Access & users

Do not put this behind an open port 53 on the internet. It is a LAN resolver: no rate limiting worth the name, and an open recursive resolver is a DDoS amplifier.

Clients

The same blocklists and rewrites on a machine that leaves the house.

⊞ Windows — WebView2

A native host around the shared console, so the UI is the same one the server ships. Runs as a service, points the adapter at 127.0.0.1, and restores your previous DNS on uninstall.

Windows 10/11x64 · arm64WebView2

◈ Linux — AppImage

One file, no install step. GUI for the desktop and a stellardns-client binary on PATH for scripts, systemd units and headless boxes.

AppImagex64 · arm64CLI + GUI

⌘ macOS — Swift

Native SwiftUI shell with a Metal-backed traffic view, universal build for Apple silicon and Intel. Ships the same Node core as the other platforms.

arm64x86_64Metal

Client packaging lives in client/ in the repository. The Node core is the part that runs everywhere; the native shells only host the UI and the service.

Updating

Two ways, both keep config.json, users, logs and TLS material.

PathWhat happensUse when
Console → UpdatesFetches the release, checks syntax, backs up, swaps, restarts, reports back. Rollback restores the previous files.Normal upgrades
sudo sh stellardns-install.shRe-runs the installer in place, keeps your config and data, restarts the unit.First install, or a broken console

The updater only ever talks to api.github.com and raw.githubusercontent.com over https, with a fixed redirect host list, a 16 MB cap, and node --check before anything is replaced. It installs nothing it has not been shown in a check, and it never auto-installs — auto-check can be turned off in config.
